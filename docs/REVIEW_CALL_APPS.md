# v0.3.0 通話アプリ対応のレビュー

対象はv0.2.0から追加したLINE・Zoom・Macの電話のプロセス分類、候補表示、モードごとの受け渡し、再検出後の選択維持です。

## 確認した設計と修正

- LINEの本体だけではLineCallや音声サービスを取りこぼすため、実機のアプリ内Helper・XPCサービスと、LINE専用のWebKit音声プロセスを同じ候補にまとめました。
- Zoomの会議／キャプチャ用Helperは別のbundle IDを使います。Zoom公式の署名・公証済みインストーラーを実行せずに展開し、`us.zoom.xos`・`us.zoom.ZoomMeeting`・`us.zoom.CptHost`・`us.zoom.caphost`を確認しました。これらを同じ候補にまとめます。
- Macの電話の本体だけでは、共有システムサービスが出す通話音声を取りこぼすため、`com.apple.TelephonyUtilities`・`com.apple.avconferenced`・FaceTime関連もまとめました。電話だけの分離は保証できないので、候補名と画面の注意文に共有通話音声であることを明示しています。
- 一般的な`line`・`phone`・`zoom`という文字列だけで新しいアプリに分類しません。bundle IDの名前空間、アプリ内の実行パス、専用WebKitプロセス名を使い、似た名前の無関係なプロセスを除外します。
- 再検出で選択がSlackやChromeへ戻ると、新しい会話アプリのHelperを更新する際に誤った経路を選ぶため、同じモードで選んだアプリのfamilyと物理マイクを維持します。終了した候補は新しい一覧から選び直します。
- 議事録モードは新しい会話アプリでも既定マイクを変更しません。通常モードの既定入力の切替／復元と、利用者が途中で変更した入力を維持する挙動を確認しました。
- インストール後の画面確認で長い説明文が右端で切れる問題を見つけ、文を折り返し、内容をウインドウ幅に収めるように修正しました。

## 実行した検証

- Intel Mac、macOS 26.6.2で `./script/build_gpt_call_mixer.sh --verify` が成功しました。
- アプリとドライバ2本をApple Silicon・Intelのユニバーサル形式でビルドし、アドホック署名・ZIP再展開後の署名・ドライバのライセンス同梱を検証しました。
- `AudioRingBufferTests`、33ケースの`AudioProcessFamilyTests`、`MeetNotesModeTests`が成功しました。LINE・Zoom・電話を両モードで選べること、グループ全体のプロセスIDをエンジンに渡すこと、HelperのID変更後にも選択を維持すること、同じブラウザ／重複プロセスの拒否を確認しています。
- 自動テストは架空の音声エンジンと隔離した設定を使います。Process Tapやマイクを起動せず、実際の既定入力も変更しません。
- 読み取り専用の`--diagnose`で、このMacのLINEと電話／共有サービスが一つずつの候補にまとまることと、既定入力が物理マイクのままであることを確認しました。
- このMacの電話アプリの「ビデオ → マイク」に両方のGPT Call Mixer仮想デバイスが表示されることを確認しました。

## 検証の限界

- このMacにはZoomクライアントがインストールされていないため、Zoomの実行中プロセス検出は未検証です。公式パッケージの構成と架空の入力で分類を確認しました。
- LINE・Zoom・電話の実通話、ChatGPTの音声を相手へ送る双方向転送、Meetでのメモ保存、長時間利用、Apple Siliconでの実行は未検証です。プロセス分類と制御のテストは、音声転送全体の実機検証を置き換えるものではありません。
- 取り込みは通話参加者やタブごとの分離ではなく、選んだアプリ／共有サービス単位です。別の会議、通知音、FaceTimeなどの音声も含む場合があります。
- 開始後に追加・再起動された音声プロセスの追跡は自動では行いません。停止→再検出→開始を使います。
- 配布ZIPはアドホック署名のローカルビルドです。Developer ID署名・公証済みのインストーラーではありません。
