# Meet議事録モードのレビュー

2026-10-08 / ソースバージョン 0.2.0

公開版 `01a96f6` と、新しい議事録モード・ユニバーサルビルドの差分を確認しました。
この文書はコードレビューとローカル検証の記録です。実会議での動作認定ではありません。

## 指摘と修正

| 指摘 | 影響 | 対応 |
| --- | --- | --- |
| 議事録モードを解除しても既定入力切替のチェックがOFFのまま残る | 通常のVoice利用へ戻ったとき、期待した仮想マイクへの切替が行われない | 通常モードでのON/OFFを保持し、戻るときに復元。再起動時の議事録モードもテスト |
| Chromeのマイク設定をサイト専用の選択として説明していた | 他サイトにも適用される既定マイク設定を、Meetだけの変更と誤解する | Chrome全体の設定であることと、終了後に戻す手順を明記 |
| メモと逐語的な文字起こしを混同し、話者分離を保証していた | 混合音声から期待どおりの参加者名・逐語録が得られると誤解する | メモと文字起こしを区別し、参加者名は引き継がれず話者分離は未検証と明記 |
| 単一CPU向けビルドでは、テスト用エンジンに実行ホストのCPUが含まれない場合がある | 別CPUだけをビルドする指定で、追加したモードテストを実行できない | 必要な場合だけホスト用エンジンも別途ビルド。Intelホストでarm64単独指定を検証 |

最初の指摘は、新しい回帰テストで修正前の失敗を確認し、修正後にPASSを確認しました。

## 確認した動作

- 議事録モードでは既定入力変更の操作を呼ばず、Slack/Discord用の物理マイクを維持します。
- 通常モードへ戻ると以前のマイク切替チェックを復元します。ON/OFFの両方と、同じモードの繰り返し更新を確認しました。
- 同じブラウザ、または重複する音声プロセスを両側に選んだ場合は開始を拒否します。
- 通常モードの停止時には元の既定入力を復元し、途中で利用者が入力を変更した場合はその選択を維持します。
- Slackの本体とHelperを同じプロセスファミリーとして検出するコードを確認しました。
- 音声経路のコードでは `→ Call` は物理マイクと会話アプリ側の音声を混ぜます。Meet側の音声はこの出力へ混ぜません。

コントローラーのテストは架空の音声エンジンと隔離したUserDefaultsを使います。
実際のマイク、Process Tap、macOSの既定入力は操作しません。
